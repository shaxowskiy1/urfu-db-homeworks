# Музыкальный стриминг

ДЗ 1: Java 17, Spring Boot 3.5.16, Spring Data JPA, Hibernate, PostgreSQL 17, Flyway, Maven.

## Запуск

Нужны JDK 17–25, Maven 3.6.3+, Docker Compose

```sh
docker compose up -d --wait
mvn spring-boot:run
```

API доступен по адресу `http://localhost:8080/api`.

Сборка исполняемого JAR:

```sh
mvn clean package
java -jar target/music-streaming-1.0.0.jar
```

Переменные приложения: `DB_URL`, `DB_USER`, `DB_PASSWORD`, `SERVER_PORT`. Значения по умолчанию: `jdbc:postgresql://localhost:5432/music`, `music`, `music`, `8080`.

Если порт PostgreSQL занят:

```sh
DB_PORT=5433 docker compose up -d --wait
DB_URL=jdbc:postgresql://localhost:5433/music mvn spring-boot:run
```

Остановка БД с сохранением данных:

```sh
docker compose down
```

## Модель

Пять сущностей:

| Сущность | Данные и связи |
| --- | --- |
| Исполнитель | Имя, список треков; двусторонняя связь один-ко-многим с треками |
| Трек | Название, жанр, длительность в секундах; связь многие-к-одному с исполнителем, один-к-одному с текстом песни |
| Текст песни | Язык и текст; композиция с треком |
| Плейлист | Название, позиции плейлиста |
| Позиция плейлиста | Две связи многие-к-одному с треком и плейлистом, порядковый номер, версия |


## Проверка

Интеграционные тесты с H2 в режиме PostgreSQL, Flyway и проверкой схемы Hibernate:

```sh
mvn test
```

Те же тесты можно выполнить на настоящем PostgreSQL в отдельной базе:

```sh
docker compose up -d --wait
docker compose exec postgres psql -U music -d postgres -c 'CREATE DATABASE music_test;'
TEST_DB_URL=jdbc:postgresql://localhost:5432/music_test TEST_DB_USER=music TEST_DB_PASSWORD=music mvn test
```

Базу `music_test` достаточно создать один раз. Тесты очищают все таблицы музыкальной модели перед каждым сценарием; `TEST_DB_URL` должен указывать на отдельную тестовую базу.

## REST API

Адрес приложения по умолчанию: `http://localhost:8080`. Для запросов с JSON-телом передавайте `Content-Type: application/json`. Для GET и DELETE тело запроса не требуется. Ответы с данными возвращаются в JSON; у `204 No Content` тело отсутствует.

Ниже приведены примеры успешных ответов API. Идентификаторы условные: используйте значения из ответов своего приложения. Все сущности используют общую последовательность, поэтому идентификаторы разных таблиц могут идти вперемешку. Примеры описывают отдельные операции и не требуют выполнения строго по порядку. Спецсимволы и кириллицу в query-параметрах нужно кодировать при отправке URL.

### 1. Создать исполнителя

Создаёт исполнителя и возвращает его идентификатор и имя.

**URL:** `POST http://localhost:8080/api/artists`

**Тело запроса:**

```json
{
  "name": "Исполнитель"
}
```

**Ожидаемый код:** `201 Created`.

**Тело ответа:**

```json
{
  "id": 1,
  "name": "Исполнитель"
}
```

**Ошибки:** `400 Bad Request` — имя отсутствует, состоит из пробелов или превышает 120 символов; некорректный JSON.

### 2. Получить исполнителей

Возвращает исполнителей по возрастанию идентификатора. Если исполнителей нет, ответ — `[]`.

**URL:** `GET http://localhost:8080/api/artists`

**Тело запроса:** отсутствует.

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
[
  {
    "id": 1,
    "name": "Исполнитель"
  }
]
```

### 3. Получить треки исполнителя

Возвращает треки исполнителя с `id = 1` по возрастанию идентификатора, включая исполнителя и текст песни. Запрос реализован через JPQL с `join fetch`. Для существующего исполнителя без треков возвращается `[]`.

**URL:** `GET http://localhost:8080/api/artists/1/tracks`

**Тело запроса:** отсутствует.

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
[
  {
    "id": 2,
    "title": "Название",
    "genre": "Rock",
    "durationSeconds": 180,
    "artist": {
      "id": 1,
      "name": "Исполнитель"
    },
    "lyrics": {
      "id": 3,
      "language": "ru",
      "content": "Текст песни"
    }
  }
]
```

**Ошибки:** `400 Bad Request` — идентификатор не является положительным целым числом; `404 Not Found` — исполнитель отсутствует.

### 4. Создать трек

Создаёт трек для существующего исполнителя. При передаче `lyrics` также создаёт текст песни.

**URL:** `POST http://localhost:8080/api/tracks`

`title` — непустая строка до 160 символов; `genre` — непустая строка до 60 символов; `durationSeconds` — положительное целое число секунд; `artistId` — обязательный положительный идентификатор. Поле `lyrics` можно опустить или передать как `null`; тогда в ответе `lyrics` будет `null`. Если текст передан, `language` должен быть непустым и не длиннее 16 символов, `content` — непустым и не длиннее 100000 символов.

**Тело запроса:**

```json
{
  "title": "Название",
  "genre": "Rock",
  "durationSeconds": 180,
  "artistId": 1,
  "lyrics": {
    "language": "ru",
    "content": "Текст песни"
  }
}
```

**Ожидаемый код:** `201 Created`.

**Тело ответа:**

```json
{
  "id": 2,
  "title": "Название",
  "genre": "Rock",
  "durationSeconds": 180,
  "artist": {
    "id": 1,
    "name": "Исполнитель"
  },
  "lyrics": {
    "id": 3,
    "language": "ru",
    "content": "Текст песни"
  }
}
```

**Ошибки:** `400 Bad Request` — не заполнены обязательные поля, нарушены ограничения или некорректный JSON; `404 Not Found` — исполнитель с указанным `artistId` отсутствует.

### 5. Получить трек

Возвращает трек с `id = 2`, вложенного исполнителя и текст песни. Если текста нет, поле `lyrics` равно `null`.

**URL:** `GET http://localhost:8080/api/tracks/2`

**Тело запроса:** отсутствует.

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
{
  "id": 2,
  "title": "Название",
  "genre": "Rock",
  "durationSeconds": 180,
  "artist": {
    "id": 1,
    "name": "Исполнитель"
  },
  "lyrics": {
    "id": 3,
    "language": "ru",
    "content": "Текст песни"
  }
}
```

**Ошибки:** `400 Bad Request` — некорректный идентификатор; `404 Not Found` — трек отсутствует.

### 6. Найти треки с динамическими фильтрами

Возвращает треки по возрастанию идентификатора. Все заполненные фильтры объединяются условием AND через Criteria API. Если совпадений нет, возвращается `[]`.

**URL:** `GET http://localhost:8080/api/tracks?title=назв&genre=Rock&artistId=1&minDuration=120&maxDuration=240`

| Параметр | Обязательный | Значение |
| --- | --- | --- |
| `title` | Нет | Подстрока названия без учёта регистра; `%` и `_` считаются обычными символами |
| `genre` | Нет | Точное совпадение жанра без учёта регистра |
| `artistId` | Нет | Положительный идентификатор исполнителя |
| `minDuration` | Нет | Минимальная длительность в секундах, включительно |
| `maxDuration` | Нет | Максимальная длительность в секундах, включительно |

Пустые строковые фильтры игнорируются. `GET http://localhost:8080/api/tracks` без параметров возвращает все треки.

**Тело запроса:** отсутствует.

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
[
  {
    "id": 2,
    "title": "Название",
    "genre": "Rock",
    "durationSeconds": 180,
    "artist": {
      "id": 1,
      "name": "Исполнитель"
    },
    "lyrics": {
      "id": 3,
      "language": "ru",
      "content": "Текст песни"
    }
  }
]
```

**Ошибки:** `400 Bad Request` — числовые параметры не являются положительными целыми числами либо `minDuration` больше `maxDuration`. Несуществующий положительный `artistId` возвращает `200 OK` с `[]`.

### 7. Найти треки по жанру

Возвращает треки указанного жанра без учёта регистра, по возрастанию идентификатора. Используется запрос из имени метода Spring Data JPA. Если совпадений нет, возвращается `[]`.

**URL:** `GET http://localhost:8080/api/tracks/by-genre?genre=Rock`

**Параметры URL:** `genre` — обязательная непустая строка.

**Тело запроса:** отсутствует.

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
[
  {
    "id": 2,
    "title": "Название",
    "genre": "Rock",
    "durationSeconds": 180,
    "artist": {
      "id": 1,
      "name": "Исполнитель"

    "lyrics": {
      "id": 3,
      "language": "ru",
      "content": "Текст песни"
    }
  }
]
```

**Ошибки:** `400 Bad Request` — обязательный параметр `genre` отсутствует, пуст или состоит из пробелов.

### 8. Найти короткие треки

Возвращает треки с длительностью не больше указанной, сначала по длительности, затем по идентификатору. Используется native SQL. Ответ содержит `artistId` и не содержит вложенных объектов исполнителя и текста песни. Если совпадений нет, возвращается `[]`.

**URL:** `GET http://localhost:8080/api/tracks/short?maxDuration=180`

**Параметры URL:** `maxDuration` — обязательное положительное целое число секунд, граница включительна.

**Тело запроса:** отсутствует.

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
[
  {
    "id": 2,
    "title": "Название",
    "genre": "Rock",
    "durationSeconds": 180,
    "artistId": 1
  }
]
```

**Ошибки:** `400 Bad Request` — параметр `maxDuration` отсутствует либо не является положительным целым числом.

### 9. Добавить или заменить текст песни

Добавляет текст к треку с `id = 2` или полностью заменяет существующий. Возвращает весь трек с новым текстом. Старая запись текста удаляется через `orphanRemoval`.

**URL:** `PUT http://localhost:8080/api/tracks/2/lyrics`

`language` — обязательная непустая строка до 16 символов; `content` — обязательная непустая строка до 100000 символов. При добавлении текста к существующему треку также возвращается `200 OK`.

**Тело запроса:**

```json
{
  "language": "en",
  "content": "New lyrics"
}
```

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
{
  "id": 2,
  "title": "Название",
  "genre": "Rock",
  "durationSeconds": 180,
  "artist": {
    "id": 1,
    "name": "Исполнитель"
  },
  "lyrics": {
    "id": 6,
    "language": "en",
    "content": "New lyrics"
  }
}
```

**Ошибки:** `400 Bad Request` — некорректный идентификатор, JSON или поля текста; `404 Not Found` — трек отсутствует.

### 10. Удалить текст песни

Удаляет текст песни у трека с `id = 2`. Сам трек сохраняется; последующее чтение трека вернёт `lyrics: null`. Если у существующего трека уже нет текста, также возвращается `204 No Content`.

**URL:** `DELETE http://localhost:8080/api/tracks/2/lyrics`

**Тело запроса:** отсутствует.

**Ожидаемый код:** `204 No Content`.

**Тело ответа:** отсутствует.

**Ошибки:** `400 Bad Request` — некорректный идентификатор; `404 Not Found` — трек отсутствует.

### 11. Создать плейлист

Создаёт пустой плейлист. Название обязательно, не должно состоять из пробелов и должно содержать не больше 160 символов.

**URL:** `POST http://localhost:8080/api/playlists`

**Тело запроса:**

```json
{
  "name": "Избранное"
}
```

**Ожидаемый код:** `201 Created`.

**Тело ответа:**

```json
{
  "id": 4,
  "name": "Избранное",
  "items": []
}
```

**Ошибки:** `400 Bad Request` — некорректное название или JSON.

### 12. Получить список плейлистов

Возвращает идентификаторы и названия плейлистов по возрастанию идентификатора. Позиции в этот ответ не включаются. Если плейлистов нет, возвращается `[]`.

**URL:** `GET http://localhost:8080/api/playlists`

**Тело запроса:** отсутствует.

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
[
  {
    "id": 4,
    "name": "Избранное"
  }
]
```

### 13. Получить плейлист с позициями

Возвращает плейлист с `id = 4` и его позиции по возрастанию `position`. Для пустого плейлиста `items` равен `[]`. Поле `id` внутри позиции — идентификатор позиции, `trackId` — идентификатор трека, `version` — текущая версия позиции для изменения.

**URL:** `GET http://localhost:8080/api/playlists/4`

**Тело запроса:** отсутствует.

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
{
  "id": 4,
  "name": "Избранное",
  "items": [
    {
      "id": 5,
      "trackId": 2,
      "title": "Название",
      "position": 1,
      "version": 0
    }
  ]
}
```

**Ошибки:** `400 Bad Request` — некорректный идентификатор; `404 Not Found` — плейлист отсутствует.

### 14. Добавить трек в плейлист

Добавляет существующий трек в существующий плейлист с указанным порядковым номером. Один трек встречается в плейлисте один раз; тот же трек можно добавить в другие плейлисты. Номера должны быть уникальными внутри плейлиста, пропуски допустимы.

**URL:** `POST http://localhost:8080/api/playlists/4/items`

`trackId` — обязательный положительный идентификатор трека; `position` — обязательное положительное целое число. В ответе `version` новой позиции равен `0`.

**Тело запроса:**

```json
{
  "trackId": 2,
  "position": 1
}
```

**Ожидаемый код:** `201 Created`.

**Тело ответа:**

```json
{
  "id": 5,
  "trackId": 2,
  "title": "Название",
  "position": 1,
  "version": 0
}
```

**Ошибки:** `400 Bad Request` — некорректный идентификатор, JSON, отсутствующий `trackId` или неположительный `trackId`/`position`; `404 Not Found` — плейлист или трек отсутствует; `409 Conflict` — трек уже добавлен либо номер занят.

### 15. Изменить позицию трека

Меняет номер позиции с `itemId = 5` в плейлисте с `id = 4`. Указывается свободный номер; остальные позиции автоматически не сдвигаются. Версию нужно взять из актуального ответа добавления, изменения позиции или чтения плейлиста.

**URL:** `PATCH http://localhost:8080/api/playlists/4/items/5`

`position` — обязательное положительное целое число; `version` — обязательное целое число от нуля. При фактическом изменении номера Hibernate увеличивает версию. Если передан текущий номер, версия может остаться прежней.

**Тело запроса:**

```json
{
  "position": 3,
  "version": 0
}
```

**Ожидаемый код:** `200 OK`.

**Тело ответа:**

```json
{
  "id": 5,
  "trackId": 2,
  "title": "Название",
  "position": 3,
  "version": 1
}
```

**Ошибки:** `400 Bad Request` — некорректные идентификаторы или JSON, неположительный `position`, отсутствующий или отрицательный `version`; `404 Not Found` — позиция не найдена в указанном плейлисте; `409 Conflict` — номер занят, версия устарела или запись была изменена параллельно.

### 16. Удалить позицию плейлиста

Удаляет позицию с `itemId = 5` из плейлиста с `id = 4`. Трек сохраняется в каталоге и в других плейлистах. Номера оставшихся позиций сохраняются.

**URL:** `DELETE http://localhost:8080/api/playlists/4/items/5`

**Тело запроса:** отсутствует.

**Ожидаемый код:** `204 No Content`.

**Тело ответа:** отсутствует.

**Ошибки:** `400 Bad Request` — некорректные идентификаторы; `404 Not Found` — плейлист или позиция в нём отсутствует; `409 Conflict` — позиция была изменена параллельно.

### Тела ошибок

Ошибки валидации тела и параметров, а также конфликты ограничений БД и оптимистической блокировки возвращаются в JSON с описанием проблемы. Пример для невалидного имени исполнителя:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "name: must not be blank",
  "instance": "/api/artists"
}
```
